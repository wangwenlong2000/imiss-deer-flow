# 城市绿地评估数据质量检查

## 影像质量

检查项：

- 文件是否存在且可读取。
- 是否为 GeoTIFF 或其他脚本支持格式。
- 是否包含红光与近红外波段。
- 是否存在明显云、云影、积雪、水体反光或裸地混淆。
- 影像日期是否处于适合识别植被的季节。

## 波段假设

当前脚本在多波段影像中默认：

- 第 3 个波段为红光。
- 第 4 个波段为近红外。

该假设适合部分常见 RGB+NIR 或 Sentinel-2 预处理栈，但不适用于所有数据。若输入为 Sentinel-2 原始多波段重排、Landsat、GF 或无人机影像，应先确认波段顺序。

如果影像只有 3 个 RGB 波段，当前脚本不能完成真实 NDVI 绿地提取。应停止运行并要求用户补充：

- 含近红外波段的多光谱 GeoTIFF；或
- 已经由其他可靠流程生成的绿地二值 GeoTIFF 掩膜 `green_mask`。

不得为了让任务继续而临时编写 ExG、可见光阈值或深度学习脚本。

## CRS 与分辨率

输出面积和斑块指标依赖像元面积。当前脚本默认 10m 像元，即每像元 100m2。

如果输入影像不是 10m 分辨率，应在结论中说明：

- 绿地覆盖率仍可作为比例参考。
- 绿地面积、平均斑块面积、人均绿地等绝对面积指标需要按真实像元大小复核。

## 边界数据

`boundary` 当前主要用于任务输入约束和后续报告说明。若需要严格按边界裁剪、分区统计，应在后续版本中增强脚本，或先用预处理 skill 完成裁剪。

## 人口数据与空间对齐

人口数据用于人均绿地和服务公平性。检查项：

- 是否与绿地栅格处于同一 CRS。
- 是否具有相近分辨率或可合理重采样。
- 是否覆盖完整 AOI。
- CSV 人口网格是否具有明确坐标字段。

当前脚本对人口栅格进行简化裁切匹配。正式评估应优先用严格重投影、重采样和分区统计流程。

## 阈值不确定性

NDVI 阈值会受季节、植被类型、传感器、土壤背景、灌木/草地状态影响。建议：

- 抽样检查 20-50 个绿地/非绿地点。
- 对 0.20、0.25、0.30、0.35 做敏感性比较。
- 在报告中说明最终阈值选择依据。

## 输出质量检查

运行完成后检查：

- `metrics.json` 是否存在并可解析。
- `green_coverage_pct` 是否在 0-100 之间。
- `n_patches` 是否异常过大或为 0。
- `green_mask` 是否为真实空间文件；若为 `.npy`，说明空间参考不足。
- `report.md` 是否生成。

如果 `check-inputs` 已返回 invalid input，不应进入 `run`，更不应创建新的脚本绕过现有脚本能力边界。
