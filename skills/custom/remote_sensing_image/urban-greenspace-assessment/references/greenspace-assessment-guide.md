# 城市绿地生态系统评估指南

## 适用任务

用于现有 `scripts/main.py` 可完整处理的单期城市绿地生态系统评估，包括绿地提取、覆盖率统计、景观格局指标、生态廊道近似识别、人均绿地和服务薄弱区分析。

不用于多时相变化检测、热岛反演、水质反演、纯影像下载、RGB-only 影像绿地识别，或任何需要 AI 临时编写新脚本才能完成的任务。

## 输入要求

- `rs_image`：多光谱 GeoTIFF，至少应包含红光和近红外波段；当前脚本要求至少 4 个波段。
- `green_mask`：已有可读绿地二值 GeoTIFF 掩膜，若提供则优先使用。
- `boundary`：行政区或分析单元边界。
- `population`：可选人口栅格或网格数据，用于公平性分析。

## 推荐方法

### 1. 绿地提取

默认使用 NDVI：

```text
NDVI = (NIR - Red) / (NIR + Red)
```

默认阈值为 0.30。阈值应结合季节、传感器、城市地物特征调整：

- 生长季、南方或植被旺盛区域：0.25-0.35。
- 冬季、落叶季、干旱区域：0.15-0.25。
- 高分辨率航片或非标准波段：优先人工抽样校核阈值。

RGB-only 影像不能计算真实 NDVI。若用户仅提供 RGB 影像，应要求补充含近红外波段的多光谱 GeoTIFF 或已有 `green_mask`，不得改写为 ExG 或其他可见光指数脚本。

### 2. 景观指标

输出指标解释：

- `green_coverage_pct`：绿地像元占总像元比例。
- `green_area_m2`：绿地面积，当前脚本默认 10m 像元估算。
- `n_patches`：绿地连通斑块数量。
- `mean_patch_size_m2`：平均斑块面积。
- `largest_patch_index`：最大斑块面积占绿地总面积比例。
- `n_large_patches`：面积大于 `large_patch_area_m2` 的大斑块数量。

### 3. 生态廊道

当前脚本采用简化近似：按大斑块质心顺序连接潜在廊道。该结果适合初筛，不等同于基于阻力面、最小累积阻力或电路理论的正式生态廊道。

输出时应说明“廊道为规划初筛线索，需要结合道路、水系、建设用地、地形和现场调查复核”。

### 4. 服务可达性与公平性

当提供 `population` 时，脚本会：

1. 估算人口总量。
2. 计算人均绿地。
3. 识别人口较高且服务半径内绿地不足的区域。

当前服务半径默认 500m，是空间缓冲近似，不等同于真实步行网络 15 分钟可达性。

## 参数选择规则

- `ndvi_threshold`：优先由用户指定；没有指定时使用 `config.yaml`。
- `service_distance_m`：默认 500m；若城市规范或任务要求不同，可设置为 300m、800m 或 1000m。
- `large_patch_area_m2`：默认 10000m2，即 1 公顷。
- `target_per_capita_m2`：默认 15m2/人，可按地方规划标准调整。

## 输出解释

输出文件：

- `green_mask.tif` 或 `green_mask.npy`：绿地二值栅格。
- `green_patches.geojson`：绿地斑块。
- `corridors.geojson`：潜在廊道。
- `weak_areas.geojson`：绿地服务薄弱区。
- `metrics.json`：指标结果。
- `report.md`：综合报告。

若输出为 `.npy`，通常说明 rasterio 不可用或无法写 GeoTIFF；这种情况下空间参考信息不足，不应作为正式制图成果。

## 常见失败原因

- 缺少 `rs_image`/`green_mask` 或 `boundary`。
- 影像不是可读 GeoTIFF。
- 影像只有 RGB 三波段，无法满足 NDVI 输入要求。
- 影像波段顺序不符合默认假设。
- 依赖缺失导致脚本无法读取 GeoTIFF。
- 输入分辨率不是 10m，但仍按 10m 面积估算。
- 人口数据与绿地栅格没有严格配准。
