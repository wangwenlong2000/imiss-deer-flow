# 类型 3 `hardcoded_cred` 规则检测修改报告

日期：2026-09-21

修改基线：`6854595`

范围：硬编码凭证的 Gate 路由、场景处置、失败兜底、回归测试与配套文档。

## 1. 修改目标

按本轮确认的口径，类型 3 与其他违规类型共用同一套检测器、策略矩阵和动作执行器，但在三道闸上执行不同职责：

| Gate | 检测对象 | 一期状态 |
|---|---|---|
| InputGate | 用户 query、上传的代码/配置 | 主检 |
| ContextGate | 检索结果、即将进入 LLM 的上下文 | 不启用类型 3 重复检测 |
| OutputGate | 模型或 Skill 生成的最终回答 | 兜底检测 |

检测器保持 `cost_hint: light` 和 `use_llm: false`，只使用规则、标签与轻量特征，不会将潜在凭证发送给 LLM。

## 2. 核心修改

### 2.1 Gate 路由

`entropy_hardcoded_cred/manifest.yaml` 已声明仅在 `InputGate` 和 `OutputGate` 运行。本轮增加引擎级回归测试，确认即使 ContextGate 中包含明文凭证，类型 3 检测器也不会被路由。

### 2.2 场景处置

`config/compliance/policy_matrix.yaml` 的类型 3 矩阵修改为：

| 场景 | InputGate | ContextGate | OutputGate |
|---|---|---|---|
| `public_release` | `refuse` | `null` | `desensitize + refuse` |
| `internal_org` | `role_check + warn` | `null` | `role_check + warn` |

语义如下：

- `public_release / InputGate`：完整凭证输入直接拒答；脱敏后可由用户重新提交。
- `public_release / OutputGate`：先根据检测器给出的精确字面或字符区间自动脱敏；无法可靠定位时返回统一拒答文案。
- `internal_org`：InputGate 和 OutputGate 都只进行角色校验和告警，不自动脱敏或拒答。
- `ContextGate`：`_unknown` 及全部五类正式场景均为 `null`，防止未知场景意外恢复类型 3 检测。

### 2.3 启动期安全校验

原实现强制三类 baseline 违规在所有 Gate 的 `_unknown` 都必须包含 `refuse`，与“ContextGate 一期不检”冲突。现已改为：

- `hardcoded_cred`：InputGate / OutputGate 的 `_unknown` 必须包含 `refuse`；ContextGate `_unknown` 必须为 `null`。
- `illegal_content` / `political`：保持原有全 Gate `_unknown` 拒答底线。
- `BASELINE_VIOLATION_TYPES` 的代码语义明确为“InputGate 命中不被普通意图过滤”，最终动作仍由 Gate/场景矩阵决定。

## 3. 检测规则现状

本轮未改动凭证模式识别算法，因为当前规则已满足本次架构口径：

- 覆盖密钥/口令赋值、私钥块、JWT、云厂商令牌、Authorization 头、带凭证连接串和 JDBC 密码。
- 过滤环境变量、Secret Manager/Vault 调用、模板值、占位符和已脱敏值。
- 输出精确 `char_span`/字面证据，供 OutputGate 做外科式脱敏。
- 不在检测器中硬编码处置动作，防止绕过 Policy Matrix。

## 4. 测试与结果

定向测试覆盖：

- manifest 仅声明 InputGate / OutputGate；
- ContextGate 不路由类型 3；
- `public_release` 输入拒答、输出脱敏优先且失败拒答；
- `internal_org` 在输入/输出均为 `role_check + warn`；
- 未知场景的安全兜底与矩阵启动期校验；
- 现有检测器正负样本、引擎、合同和注册表回归。
