## 四项需求逐一评估

### 1. ❌ 确认视频中具体人员的身份

**无法支持。** 原因有三层：

- **数据层面**：本次检测在当前片段中未检测到任何行人，可能因画面角度、分辨率或光照条件导致模型未识别。即使后续帧有行人，也仅能提供"有人出现在某位置"的客观事实。
- **技术层面**：视频目标检测只能识别"这是一个人/车"，**不具备人脸识别、身份匹配功能**。人脸身份确认需要对接公安人脸识别数据库或已知人员库进行比对，这需要专门的活体检测、人脸对齐和特征向量比对能力。
- **合规层面**：即使用户拥有合法授权，系统目前也未集成人脸识别服务。

### 2. ❌ 读取模糊车牌

**无法支持。**

- 当前 YOLOv8n 模型仅做通用目标检测，**不具备 OCR（光学字符识别）能力**。
- 即使车牌在画面中清晰可见，也需要专门的车牌检测 + 字符识别 pipeline（如 CRNN + Attention 架构）。
- 你明确提到车牌是"模糊"的——这进一步降低了任何识别方案的成功率。
- 如需实现，需额外接入车牌识别专用模型（如 PaddleOCR、EasyPR）并保证原始视频分辨率和清晰度足够。

### 3. ❌ 生成全市热力图

**无法支持。**

- 单一路口的视频片段仅提供局部观测，**覆盖范围远不足以代表全市交通状况**。
- 全市热力图需要多路摄像头的实时定位数据（经纬度坐标）、车辆计数或速度信息，通常需要城市级 IoT 平台或交管部门的数据接口。
- 当前只有 `CAM_DEERFLOW_001` 一个摄像头视角，缺少地理坐标映射信息。

### 4. ❌ 接入实时 RTSP 流

**无法支持。**

- 当前仅有本地 MP4 文件，系统未配置任何 RTSP 推流/拉流基础设施。
- 实时接入需要：RTSP 服务器（如 ZLMediaKit / SRS）、网络通道、鉴权机制、以及持续的解码与分析 pipeline。
- 这属于系统基础设施层面的部署工作，不是一次性分析任务。
