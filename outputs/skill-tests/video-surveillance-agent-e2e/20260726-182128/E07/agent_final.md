根据 `human-review-routing` 技能的工作流定义和视频监控系统的通用规则，以下结果**必须进入人工复核**：

---

## 一、事件置信度低 → 必审

| 触发条件 | 判定标准 | 必审结果类型 |
|---------|---------|------------|
| 模型输出置信度 < 默认阈值（通常 0.85） | `event.confidence < default_review_threshold` | 该事件的完整证据帧、检测框、推理日志 |
| 置信度处于"灰色区间" | 置信度在阈值 ±0.1 范围内 | 同上 |
| 多模型/多帧结论不一致 | 不同时间窗口或不同模型对同一画面判断矛盾 | 原始视频片段 + 各模型输出对比 |

> **核心原则**：置信度低于阈值的告警不能自动处置，必须由人工确认是真实事件还是误报。

---

## 二、摄像头画面有遮挡/降级 → 必审

通过 `camera-health-check` 判定的以下状态均触发复核：

| 相机健康状态 | 说明 | 必审内容 |
|------------|------|---------|
| **Occluded（遮挡）** | 画面有效可视面积不足，如树叶、建筑物、雾气遮挡 | 被遮挡区域的检测记录、相邻摄像头视角 |
| **Blurred / Corrupted（模糊/损坏）** | 画面质量下降导致检测不可靠 | 未受遮挡时段的历史数据对比 |
| **Frozen（冻结）** | 画面长时间静止，检测可能失效 | 事件发生前后时间窗的原始帧 |
| **Offline / Unavailable** | 相机离线 | 该时间段内其他相邻相机的替代证据 |
| **Shifted（偏移）** | 镜头角度漂移，ROI 区域不匹配 | ROI 重新标定记录 |

> **核心原则**：相机健康降级期间产生的任何事件结果，其可信度需要人工二次验证。

---

## 三、涉及执法的高风险事件 → 必审

无论置信度高低，以下事件类型因涉及法律后果，一律进入强制复核队列：

| 高风险事件类型 | 原因 | 必须附带的上下文 |
|--------------|------|----------------|
| **人员控制/抓捕** | 涉及人身自由限制，需合法性审查 | 完整视频切片 + 涉事人员标识 |
| **交通事故定责** | 涉及责任划分和法律赔偿 | 多角度证据帧 + 车辆轨迹 |
| **烟火/火灾报警** | 可能引发应急响应和公共安全事件 | 烟/火检测帧 + 热力图证据 |
| **入侵/越界（敏感区域）** | 涉及安防等级和安全合规 | 入侵路径轨迹 + 时间线 |
| **打架/暴力冲突** | 涉及治安案件取证 | 冲突过程视频 + 人物识别 |
| **其他标记为 high_risk_event_types 的事件** | 系统配置的执法相关事件 | 完整证据包 |

---

## 四、其他必审场景

- **新接入摄像头**（newly added camera signals）：模型尚未充分适配，误报率高
- **ROI 区域变更**：目标区域调整后，历史基线失效
- **跨相机事件关联**：多个相机联合判定的一致性需要人工校验

---

## 五、复核工单的数据要求

进入人工复核时，系统必须挂载以下上下文要素：

1. **原生视频帧**（Evidence Frames）— 事件发生前后的关键帧序列
2. **检测框坐标**（Bounding Boxes）— 模型输出的目标位置信息
3. **模型推理日志** — 置信度分数、特征向量摘要
4. **时间窗范围** — 事件起止时间的精确到秒级标注
5. **相机健康状态报告** — 当前及事件发生时段的相机质量评分
6. **相邻相机视角**（可选）— 用于交叉验证

复核结论需以结构化格式回传：`confirmed_event`（确认）、`false_positive`（误报）、`needs_reanalysis`（需重新分析）。

---

**总结**：当置信度低于 0.85 阈值、相机健康状态为遮挡/模糊/冻结等任一降级项、或事件属于 high_risk_event_types 列表中的执法相关类型时，该事件及其全部关联证据**必须进入人工复核队列**，不得仅凭自动化结果直接处置。
