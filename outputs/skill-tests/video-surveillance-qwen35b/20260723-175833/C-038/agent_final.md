根据 `human-review-routing` 技能的核心路由逻辑，结合视频监控业务规范，以下结果**必须进入人工复核队列**：

---

## 四类强制人工复核条件

### 1. 置信度低于阈值 — `confidence_below_threshold`

当事件检测的 AI 置信度低于配置阈值时，系统自动标记为待复核。

- **默认阈值**：`0.85`（85%）
- **可按事件类型差异化配置**，例如：
  - 打架/摔倒等安全类事件 → 阈值可设为 `0.90`
  - 违停/占道等管理类事件 → 阈值可设为 `0.75`
- **具体触发场景**：
  - AI 判定置信度仅为 `0.60~0.80`，属于"疑似但不确定"区间
  - 多帧检测结果置信度波动大、一致性差
  - LLM 审帧后的综合评分未达到通过线

### 2. 高风险事件类型 — `high_risk_event_type`

即使用户置信度达标，以下高危事件类型也**无条件进入人工复核**：

| 类别 | 典型事件类型 |
|------|-------------|
| 人身安全 | 打架斗殴、人员摔倒、突发聚集 |
| 消防安全 | 烟火检测、烟雾报警 |
| 交通执法 | 交通事故、违章取证、闯卡 |
| 安防入侵 | 越界入侵、禁区闯入、尾随 |

这类事件一旦误判或漏判，可能造成严重后果，因此即使 AI 判定可靠也必须经过人工二次确认。

### 3. 摄像头画面质量降级 — `camera_health_degraded`

当关联摄像头的健康状态为 `degraded`（降级）时，无论事件置信度如何，均需复核。包括以下具体情形：

- **画面遮挡**：树叶、广告牌、施工围挡等遮挡视场超过设定比例
- **画质劣化**：模糊、雪花噪点、曝光异常
- **运行异常**：离线、黑屏、画面冻结、镜头移位
- **新增信号**：新接入的摄像头首次产生告警信号

核心原则：**视觉数据质量不可靠时，AI 判定不具备独立结论效力。**

### 4. 涉及执法影响 — `affects_enforcement`

当事件被标记为可能作为行政执法证据使用时，必须人工复核。包括但不限于：

- 将用于行政处罚的交通违法取证
- 城管执法中的占道经营、违建认定
- 应急管理部门的事故责任调查
- 任何需要出具法律证据链的场景

**这是合规性要求，而非技术判断。**

## 复核决策矩阵

```
┌──────────────────┬────────────┬────────────┬─────────────┬──────────────┐
│  条件维度        │ 置信度低   │ 画面遮挡   │ 涉及执法    │ 综合判定     │
├──────────────────┼────────────┼────────────┼─────────────┼──────────────┤
│ 必须复核         │ ✓ 阈值以下 │ ✓ 降级状态 │ ✓ 是        │ 任一满足即入 │
│ 优先级           │ P2         │ P1(高)     │ P0(最高)    │ 取最高优先级  │
│ 豁免可能性       │ 无         │ 无         │ 绝对禁止    │ —            │
└──────────────────┴────────────┴────────────┴─────────────┴──────────────┘
```

---

## 输出格式

每个事件的复核路由结果包含以下字段：

| 字段 | 说明 |
|------|------|
| `event_id` | 事件唯一标识 |
| `review_required` | 布尔值，是否需复核 |
| `reasons` | 触发原因列表（如 `["confidence_below_threshold", "affects_enforcement"]`） |
| `review_threshold` | 使用的判定阈值 |
| `queue` | `"manual_review"` 或 `"auto_pass"` |

---

**总结**：置信度低、画面有遮挡（摄像头降级）、涉及执法这三类情况，只要**任一条件满足**，结果就必须进入人工复核队列，没有任何豁免空间。其中涉及执法的优先级最高，画面降级的优先级次之，置信度偏低排在第三位。
