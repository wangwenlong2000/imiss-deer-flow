## 1. 确认具体人员身份 — ❌ 无法支持

本次检测在首5秒共6帧中**未检测到任何行人（person）**，仅识别出车辆（bus 9辆、car 46辆）。即便扩展全片搜索到行人，当前数据也无法确认其真实身份：

- **缺少人脸识别基础设施**：没有人脸对齐、特征提取、比对库（如公安人口库或门禁系统数据库）
- **缺少关联数据源**：无工牌信息、访客登记、手机MAC地址等交叉验证手段
- **单摄像头视角局限**：即使拍到清晰人脸，也只能给出"相似度最高的匹配候选人"，而非确定性结论

> **需要补充的能力**：人脸检测+特征提取模型 + 待比对的人员底库 + 合规的身份核验流程。

## 2. 读取模糊车牌 — ⚠️ 能力存疑，大概率不可靠

即使视频中存在清晰可见的车牌，当前数据也存在以下限制：

- **YOLOv8n 仅做目标检测**：它只能框出车牌位置，不具备OCR文字识别能力
- **视频分辨率未知**：若车辆距离较远或运动模糊，车牌像素可能不足20×40，超出可读范围
- **无牌照解析管线**：缺少专门的License Plate Recognition (LPR/ANPR) 模块和字符级后处理

> **需要补充的能力**：车牌定位 → ROI裁剪 → OCR引擎（如PaddleOCR/CRNN）→ 字符置信度过滤。同时建议提供至少一段车辆近距离通过的片段以提高成功率。

## 3. 生成全市热力图 — ❌ 无法支持

从当前数据出发，这一需求存在根本性的数据缺口：

| 缺口 | 说明 |
|------|------|
| **空间覆盖** | 仅1个摄像头（CAM_DEERFLOW_001），代表单一地点，无法反映全市分布 |
| **地理映射** | 缺少摄像头的经纬度坐标和视场角标定，无法将像素坐标映射到地图 |
| **时间跨度** | 仅5秒采样，不足以支撑有意义的时空热力分析 |
| **聚合维度** | 全市热力图需要多路摄像头数据的时空汇聚与插值 |

> **需要补充的能力**：全市各路口/区域摄像头的实时检测输出 + GPS坐标 + 统一的地理坐标系转换 + GIS可视化工具（如Mapbox/Leaflet）。

## 4. 接入实时 RTSP — ❌ 无法由现有数据实现

这是一个**系统架构层面**的需求，不是数据分析问题：

- 当前文件是静态本地视频 `/mnt/user-data/uploads/Trafic.mp4`
- RTSP接入需要：网络可达的RTSP流地址、流媒体服务器（如GStreamer/NVS）、持续推流管道、与检测引擎的实时对接
- 这不是通过已有数据能"算出来"的结果，而是需要额外部署的基础设施

> **需要补充的能力**：RTSP流URL列表 + 流媒体拉取服务 + 实时推理管道 + 低延迟解码器。
