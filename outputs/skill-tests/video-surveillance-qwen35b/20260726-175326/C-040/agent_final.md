## 四项需求的可行性评估

### 1. ❌ 确认具体人员身份 — **无法支持**

- 检测框中没有任何 `person` 类别的目标（本次检测未发现行人）
- 即使有行人，YOLOv8n 仅输出矩形检测框，不包含人脸特征、身份标签或 ReID（行人重识别）能力
- 没有关联公安身份库、人脸识别模型或数据库查询接口
- **需要额外条件**：高清人脸抓拍相机 + 人脸识别模型 + 身份数据库对接

### 2. ❌ 读取模糊车牌 — **无法支持**

- 当前 YOLOv8n 仅输出车辆整体边界框（如 `[421.48, 348.23, 522.5, 443.23]`），不裁剪车牌区域
- 视频中车辆距离较远、分辨率有限，车牌区域在像素级极度模糊
- 没有部署 OCR / 专用车牌识别（LPR/ANPR）模型
- **需要额外条件**：高分辨率相机 + 车牌裁剪 + ANPR 识别模型 + 图像增强预处理

### 3. ❌ 生成全市热力图 — **无法支持**

- 单台摄像机 `CAM_DEERFLOW_001` 的视场覆盖范围有限，仅为局部路口/路段
- 检测框给出的是 **像素坐标**，不是 GPS 经纬度坐标
- 缺少相机的外参标定参数（焦距、安装高度、俯仰角等），无法将像素坐标反算为地理坐标
- "全市"级别热力图需要多路相机融合、GPS 定位或电子围栏数据
- **需要额外条件**：多路带 GPS 标记的相机 + 相机标定参数 + GIS 地图引擎

### 4. ⚠️ 接入实时 RTSP — **部分能力具备，需外部配置**

- 当前 `video_object_analytics` 工具本身可以接受任意本地视频路径进行分析
- 但 **RTSP 流接入** 需要：
  - 平台侧配置 RTSP 推流地址、认证凭证
  - 流媒体服务组件（如 GStreamer / FFmpeg 拉流）
  - 实时推理管道和消息队列
- 这些属于 **基础设施配置**，不在当前运行环境中预设
- **需要额外条件**：RTSP 服务端点 + 网络连通性 + 流媒体中间件
