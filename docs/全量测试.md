# 视频监控场景测试矩阵

本文用于测试 DeerFlow 在视频监控场景下的 skill 路由、数据准备、依赖安装和边界行为。

## 核心边界

- 事件语义判断统一走 `single-video-event-analysis`：先抽帧，再由支持视觉的 LLM 按时间顺序审帧，输出 `visual_timeline` 和 `events`。
- `object-detection` 只输出人、车等对象框和置信度；`object-tracking` 只做跨帧轨迹；`roi-mapping` 只做几何匹配。它们不能直接判断打架、摔倒、车祸、拥堵、入侵、占道、烟火等事件。
- 证据类 skill 只打包、截图、截片段、打码，不改变事件结论。
- 视频语义向量检索/向量入库才需要 StreetModel/Qwen3-VL 相关 MCP 或模型服务。

## 典型问题与 Skill 路由

| 编号 | 典型用户问题/测试点 | 应调用 skill 链路 | 需要的数据 | 期望检查点 | MCP/模型要求 |
| --- | --- | --- | --- | --- | --- |
| S01 | “这段监控视频有没有异常？” | `single-video-event-analysis` | `video_path`、`camera_id`、`target_events`、输出目录 | 生成 `review_manifest.json`；LLM 输出时间线、事件、证据帧、置信度、`requires_review` | 不需要 MCP；需要支持视觉的 LLM |
| S02 | “是否发生打架/摔倒/车祸/烟火/入侵/占道？” | `single-video-event-analysis` | 单视频、目标事件列表、摄像头时间/地点可选 | 只基于可见帧给结论；证据不足应输出 `unknown` 或 `requires_review=true` | 不需要 MCP；需要视觉 LLM |
| S03 | “只帮我抽关键帧/做场景切分” | `analyze-video` 或 `frame-sampling` | 视频路径、采样策略 | 输出帧图片、时间戳、metadata；不输出事件结论 | 不需要 MCP |
| S04 | “规范化一个本地视频并读取视频元数据” | `video-stream-ingestion` | `video_path`/`file_path`、`camera_id`、`source_type=local_file` | 输出 `raw_segment_uri`、宽高、时长、会话元数据 | 不需要 MCP |
| S05 | “摄像头是否黑屏/模糊/遮挡/冻结？” | `frame-sampling` -> `camera-health-check` | 视频或帧 JSON、`camera_id`、可选健康状态覆盖配置 | 输出 `health_status`、`health_score`、问题列表 | 不需要 MCP |
| S06 | “检测画面里有多少人/车/公交/货车？” | `frame-sampling` -> `object-detection` | 视频或帧 JSON、目标标签、YOLO 模型配置 | 输出每帧对象、label、confidence、bbox；不生成事件 | 不需要 MCP；需要 YOLO |
| S07 | “跟踪车辆/人员轨迹，判断是否移动或停留” | `object-detection` -> `object-tracking` | `detections_json`、`camera_id` | 输出 `track_id`、轨迹、持续时间、movement_state | 不需要 MCP |
| S08 | “目标是否在指定 ROI/人行道/禁停区内？” | `object-tracking` -> `roi-mapping` | `tracks_json` 或对象框、`camera_id`、ROI 多边形 | 输出 ROI 命中、overlap_ratio、confidence；不输出违停/入侵结论 | 不需要 MCP |
| S09 | “把事件截图作为证据保存” | `single-video-event-analysis` -> `evidence-snapshot` | 事件 JSON、帧 JSON、`evidence_frame_ids` | 输出截图 URI、SHA-256、创建时间、打码状态 | 不需要 MCP |
| S10 | “截取事件前后几秒的视频片段” | `single-video-event-analysis` -> `video-segment-extraction` | 事件时间、原视频路径、pre/post 秒数 | 输出可播放 MP4、片段起止时间 | 不需要 MCP |
| S11 | “对证据图片里的人脸/车牌打码” | `evidence-snapshot` -> `privacy-masking` | 证据图片 URI、显式 `sensitive_regions` bbox | 输出打码图片 URI、mask 方法、区域列表 | 不需要 MCP；该 skill 不自动检测人脸/车牌 |
| S12 | “多个候选事件是不是重复报警？” | `duplicate-event-merge` | 事件候选列表 | 按摄像头、事件类型、时间窗、ROI、证据帧合并 | 不需要 MCP |
| S13 | “哪些事件需要人工复核？” | `human-review-routing` | 事件 JSON、摄像头健康状态、复核阈值配置 | 高风险、低置信度、画质差、新摄像头、执法影响进入复核 | 不需要 MCP |
| S14 | “批量导入一批监控视频到视频库” | `batch-video-ingestion` | 视频目录或 manifest、ES 配置、入库模式 | `metadata_only` 快速入库；`object_detection` 慢但含目标摘要 | 不需要 MCP；内容检测模式需要 YOLO |
| S15 | “按时间/摄像头/地点/标签搜索视频” | `video-search` | 已入库 ES 文档、query、过滤条件 | 返回命中列表、score、source metadata | 不需要 MCP |
| S16 | “统计某摄像头一天内人车数量/按类别汇总” | `object-statistics` | ES 视频库记录，或本地 detections/tracks JSON | 输出总数、按 label/camera/time/movement 分组 | 不需要 MCP |
| S17 | “给检索结果或事件生成取证包” | `evidence-package-generation` | `video_id`、事件 JSON 或搜索结果 JSON、ES 配置 | 输出 package manifest、截图/片段、hash | 不需要 MCP |
| S18 | “给视频生成向量，后续做语义检索” | 优先 MCP `streetmodel-video-embedding`；fallback `video-embedding-index` | 已入库视频文档或可映射视频路径、ES、StreetModel 配置 | 写入个人向量索引，默认 `huangxiao-video-library-vector-v1`，2048 维字段 | 需要 MCP/StreetModel/Qwen3-VL-Embedding-2B |
| S19 | “用自然语言语义搜索已入库视频，如夜晚路口很多车” | `video-search --embedding-provider streetmodel`，或先 `video-embedding-index --query` 生成 query vector | 已有视频向量索引、query、StreetModel 配置 | 文本 query 变 2048 维向量后检索视频向量字段 | 需要 StreetModel 模型服务；有 MCP 时优先 MCP |
| S20 | “RTSP/GB28181 实时流接入” | 当前无对应 skill | RTSP/平台接入信息 | 应明确不支持实时流，当前只规范化本地文件 | 不适用 |

## 推荐场景组合

### 单视频事件分析链路

```text
single-video-event-analysis
  -> evidence-snapshot
  -> video-segment-extraction
  -> privacy-masking
  -> human-review-routing
  -> duplicate-event-merge
```

重点测：

- 抽帧 manifest 是否生成。
- Agent/LLM 是否按帧审查，而不是直接凭文件名猜测。
- 事件是否引用 `evidence_frame_ids`。
- 低置信度、高风险事件是否进入人工复核。
- 模糊、遮挡、画面稀疏时是否保守输出。

### 对象分析链路

```text
frame-sampling
  -> object-detection
  -> object-tracking
  -> roi-mapping
  -> object-statistics
```

重点测：

- YOLO 依赖缺失时是否返回明确错误。
- `object-detection` 是否只输出对象，不输出事件。
- ROI 命中是否只作为几何结果，不直接判断“违停/入侵”。
- 空检测、无 ROI、无轨迹时是否稳定返回空结果。

### 视频库与证据链路

```text
batch-video-ingestion
  -> video-search
  -> object-statistics
  -> evidence-package-generation
```

重点测：

- `metadata_only` 和 `object_detection` 两种入库模式是否都能跑。
- ES 不可用、索引不存在、权限错误时是否给出可诊断错误。
- 检索结果生成证据包时，截图和短片段路径是否可用。

### 语义向量检索链路

```text
streetmodel-video-embedding MCP
  -> streetmodel_health
  -> streetmodel_embed_video / streetmodel_embed_query
  -> video-search semantic
```

fallback：

```text
video-embedding-index --embedding-provider streetmodel
video-search --embedding-provider streetmodel --vector-query-mode semantic
```

重点测：

- MCP 是否暴露 `streetmodel_health`、`streetmodel_embed_video`、`streetmodel_embed_query`。
- StreetModel `/health`、`/models` 是否可访问，模型名是否为 `Qwen3-VL-Embedding-2B`。
- 视频路径是否能从 DeerFlow 映射到 GPU 节点可访问路径。
- 长视频是否先生成 frame-proxy MP4。
- 写入目标索引是否是个人索引，避免误写共享索引。

## 依赖清单

| 依赖类别 | 需要安装/准备 | 涉及 skill | 是否 MCP/模型相关 |
| --- | --- | --- | --- |
| Python 基础 | Python 3.10+，`PyYAML>=6.0` | 多数 custom skill | 否 |
| 视频处理工具 | `ffmpeg`、`ffprobe` | `analyze-video`、`single-video-event-analysis`、`video-stream-ingestion`、`video-segment-extraction`、`ffmpeg-utils`、`video-embedding-index` frame-proxy | 否；但 StreetModel 视频向量预处理也需要 |
| OpenCV | `opencv-python` 或 `opencv-python-headless` | `frame-sampling`、`evidence-snapshot`、`privacy-masking` | 否 |
| YOLO | `ultralytics`，模型权重 `skills/custom/models/yolov8n.pt` | `object-detection`、`batch-video-ingestion --analysis-mode object_detection` | 否 |
| 本地文本向量 fallback | `sentence-transformers` | `video-embedding-index --embedding-provider sentence-transformers` | 否；不是 StreetModel |
| Elasticsearch 服务 | ES 服务、`ES_URL`、`ES_USERNAME`、`ES_PASSWORD` 或配置文件 | `batch-video-ingestion`、`video-search`、`object-statistics`、`evidence-package-generation`、`video-embedding-index` | 否；语义向量写入也依赖 ES |
| 视觉 LLM | DeerFlow 当前模型需 `supports_vision: true`，Agent 能查看抽帧图片 | `single-video-event-analysis` 的最终事件结论 | 不是 MCP；但属于模型能力要求 |
| StreetModel 模型服务 | `Qwen3-VL-Embedding-2B`、`streetmodel_embedding.base_url`、2048 维向量字段 | `video-embedding-index --embedding-provider streetmodel`、`video-search --embedding-provider streetmodel` | 是，模型服务相关 |
| StreetModel MCP | `streetmodel-video-embedding` MCP server，backend 虚拟环境里有 MCP SDK，`scripts/streetmodel-video-embedding-mcp` 可执行，extensions 配置启用 | `streetmodel_health`、`streetmodel_embed_video`、`streetmodel_embed_query` | 是，MCP 相关 |
| 共享视频目录 | `deerflow_path_prefix` 与 `streetmodel_path_prefix` 同时可访问或可映射 | StreetModel 视频 embedding | 是，视频向量必测 |

仓库里的 custom skill 依赖文件为：

```bash
pip install -r skills/custom/requirements.txt
```

该文件包含：

```text
opencv-python
ultralytics
PyYAML>=6.0
sentence-transformers
```

系统包仍需单独安装：

```bash
ffmpeg
ffprobe
```

## MCP/StreetModel 专项标注

只有以下场景需要特别标注 MCP/模型服务：

| 场景 | MCP 工具 | 模型/服务 | 额外条件 |
| --- | --- | --- | --- |
| StreetModel 健康检查 | `streetmodel_health` | StreetModel `/health`、`/models` | MCP server 已启用；`STREETMODEL_BASE_URL` 或 `config.yaml` 可用 |
| 单视频生成视频向量 | `streetmodel_embed_video` | `Qwen3-VL-Embedding-2B` | 视频路径必须在 GPU 节点可读，或可复制到共享目录 |
| 文本 query 生成语义向量 | `streetmodel_embed_query` | `Qwen3-VL-Embedding-2B` text embedding | 可选择写出 query vector JSON 给 `video-search` |
| 语义视频检索 | 可先用 MCP 生成 query vector，也可 CLI 直连 StreetModel | ES 向量索引 + StreetModel query embedding | 目标索引已有 `video_vector-Qwen3-VL-Embedding-2B_urban_governance` |

当前历史测试记录中，StreetModel 文本 query embedding 已成功；视频 embedding 主要风险在共享目录权限和 GPU 节点路径可见性。测试时建议先跑 `streetmodel_health`，再用一个确认位于 `/nfsdat2/home/xhuangslm/shared_videos/...` 的短视频做最小闭环。

## 建议的最小回归集

1. `Trafic.mp4` 跑 `single-video-event-analysis`，确认能生成 manifest，LLM 输出事件或无事件结论。
2. `fight.mp4` 跑 `single-video-event-analysis`，确认高风险事件进入人工复核。
3. `07_007.avi` 跑 `batch-video-ingestion --analysis-mode object_detection`，再跑 `video-search` 和 `object-statistics`。
4. 对一个事件候选跑 `evidence-snapshot`、`video-segment-extraction`、`privacy-masking`、`human-review-routing`。
5. 跑 `video-embedding-index --embedding-provider deterministic-hash` 验证 ES 向量写入基础链路。
6. 跑 `streetmodel_health` 和 `streetmodel_embed_query` 验证 MCP/StreetModel 文本向量链路。
7. 准备一个 StreetModel 可访问短视频，跑 `streetmodel_embed_video` 验证视频向量闭环。

## 常见失败点

| 失败点 | 典型表现 | 优先排查 |
| --- | --- | --- |
| 缺 `ffmpeg`/`ffprobe` | 抽帧、探测、剪辑失败 | 系统包是否安装，容器 PATH 是否可见 |
| 缺 OpenCV | 抽样帧、打码、证据图处理失败 | `opencv-python` 是否安装 |
| 缺 YOLO/模型权重 | `YOLO_DEPENDENCY_MISSING`、`YOLO_MODEL_NOT_FOUND` | `ultralytics` 和 `yolov8n.pt` 路径 |
| 视觉模型未启用 | 只能生成 manifest，不能可靠审帧 | `config.yaml` 中模型 `supports_vision: true` |
| ES 不可用 | 入库、搜索、统计、证据包失败 | `ES_URL`、账号、索引、网络 |
| StreetModel 不可用 | query/video embedding 失败 | `/health`、`/models`、base_url、模型名 |
| 共享目录不可见 | 视频 embedding 报路径不存在或复制失败 | `deerflow_path_prefix`、`streetmodel_path_prefix`、目录权限 |
| 误把 YOLO 当事件检测 | 系统直接用 bbox 判断打架/拥堵 | 路由应回到 `single-video-event-analysis` |
