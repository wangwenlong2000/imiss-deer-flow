# 合规评测策略问题清单

## 1. 文档目的

本文档整理依据《合规评测标注指南 7.23》开展测试后发现的合规评测策略问题，供违规类型检测器、标注数据和评测规则负责人修订使用。

本文档仅包含合规评测策略自身的问题，包括：

- 违规类型定义与检测规则；
- 标注样本与训练数据覆盖；
- 检测器准确率、召回率和跨数据类型泛化；
- 指南内部的业务口径冲突；
- 需要合规负责人确认的处置语义。

IntentGuard、场景传递、移动端 SSE、输入结构解析和 DeerFlow 检测器路由等工程问题不在本文档范围内，由 DeerFlow 集成侧另行处理。

## 2. 测试依据与范围

测试依据：

- `合规评测标注指南7.23.docx`；
- 十类违规原始标注语料，共 2172 条；
- 第 1、2 类冻结测试集；
- 第 4、5 类冻结测试集；
- 第 8、9、10 类模型支持测试集；
- 当前启用的规则检测器和 TF-IDF + kNN 模型。

测试覆盖：

- 10 类违规类型；
- InputGate、ContextGate、OutputGate；
- self_use、internal_org、cross_org、public_release、research_anon；
- 电话网络、网络流量、程序代码、政策法规、遥感、时空轨迹、统计年鉴、街景、交通流量和视频监控等数据类型。

说明：2172 条全量语料测试关闭了第 6、7 类的在线 LLM 边界复核，以保证测试可重复并避免大规模外部 API 调用。因此第 7 类结果反映的是本地规则检测底线能力，生产环境启用 LLM 后可能有所变化，但需要另行建立固定模型、固定提示词的可复现评测。

## 3. 总体结果

### 3.1 冻结测试集

| 检测范围 | 指标 |
|---|---:|
| struct_id | F1 95.83% |
| geo_loc | F1 97.96% |
| illegal_content / political | 准确率 95.00% |
| video_meta_leak / re_identify / domain 支持集 | 准确率 98.21% |

### 3.2 十类全量语料

| 违规类型 | 精确率 | 召回率 | F1 | 结论 |
|---|---:|---:|---:|---|
| struct_id | 91.41% | 100.00% | 95.51% | 良好 |
| geo_loc | 99.10% | 91.67% | 95.24% | 良好 |
| hardcoded_cred | 95.39% | 96.67% | 96.03% | 良好 |
| illegal_content | 99.33% | 98.68% | 99.00% | 良好，仍有边界漏检 |
| political | 98.31% | 99.15% | 98.72% | 良好，仍有语境误报 |
| text_id | 99.19% | 84.72% | 91.39% | 基本合格，召回率偏低 |
| confidential | 100.00% | 43.75% | 60.87% | 明显不足 |
| video_meta_leak | 100.00% | 74.43% | 85.34% | 勉强达到总体线 |
| re_identify | 100.00% | 63.70% | 77.82% | 不足 |
| domain | 93.75% | 55.05% | 69.36% | 明显不足 |

十类宏平均 F1 约为 86.93%，但第 7、9、10 类明显拖后腿，不能仅以总体平均值判断系统已经满足要求。

### 3.3 数据类型泛化

| 数据类型 | F1 |
|---|---:|
| network_flow | 78.01% |
| phone_network | 89.51% |
| policy_regulation | 93.79% |
| program_code | 96.59% |
| satellite_remote_sensing | 61.39% |
| spatiotemporal_trajectory | 84.42% |

指南要求各数据类型最低准确能力不低于 75%。卫星遥感和统计年鉴明显低于目标，网络流量也接近下限。

## 4. 需要合规评测负责人处理的问题

### 4.1 confidential 检测召回率过低

现状：

- 精确率 100%，说明当前规则比较保守；
- 召回率只有 43.75%；
- 112 条正样本中漏检 63 条。

典型漏检集中在统计年鉴中的内部材料、密级信息、未公开经营信息和内部数据说明，例如：

- `stat-yearbook-confidential-state-secret-001`；
- `stat-yearbook-confidential-state-secret-002`；
- `stat-yearbook-confidential-state-secret-003`；
- `stat-yearbook-confidential-state-secret-004`；
- `stat-yearbook-confidential-state-secret-005`。

建议：

1. 补充密级、内部资料、未公开预测、内部口径、客户名单、报价策略等规则组合；
2. 分开定义“普通内部信息”“商业秘密”“国家秘密或工作秘密”，避免全部混为 confidential；
3. 增加统计年鉴、政策材料和网络流量中的正负边界样本；
4. 对 LLM 边界复核建立固定模型和固定提示词评测，不能只依赖实时模型效果；
5. 明确未提供甲方内部制度时哪些样本必须进入 manual_review。

验收建议：

- 独立冻结集 F1 不低于 85%；
- 召回率不低于 80%；
- 公开年报、公开汇总数据等负样本不得因“内部、报告、数据”等单一关键词误报。

### 4.2 re_identify 跨来源泛化不足

现状：

- 全量 F1 为 77.82%；
- 召回率为 63.70%；
- 146 条正样本中漏检 53 条；
- 56 条模型支持集表现很好，但扩展到统计年鉴等来源后明显下降。

典型漏检包括：

- `stat-yearbook-re_identify-final-068`；
- `stat-yearbook-re_identify-final-069`；
- `stat-yearbook-re_identify-final-070`；
- `stat-yearbook-re_identify-final-071`；
- `stat-yearbook-re_identify-final-072`。

建议：

1. 扩充统计年鉴、电话网络、轨迹和交通数据的多属性组合样本；
2. 不仅学习固定文本相似度，还应显式计算地域、年龄、职业、时间、疾病或事件等属性组合；
3. 增加区县级汇总、大样本统计等近似负样本，防止过度拦截；
4. 将低相似度预测真正降级为不命中或人工复核，而不是仍作为确定违规进入拒答策略；
5. 独立划分跨数据来源测试集，禁止训练集近邻进入测试集。

验收建议：

- 跨来源冻结集 F1 不低于 85%；
- 召回率不低于 80%；
- 区县级汇总且样本量充足的统计报告不得被判为再识别风险。

### 4.3 domain 检测召回率过低

现状：

- 全量 F1 为 69.36%；
- 召回率为 55.05%；
- 109 条正样本中漏检 49 条。

典型漏检集中在统计年鉴和跨来源城市治理数据：

- `stat-yearbook-domain-supplement-016`；
- `stat-yearbook-domain-supplement-017`；
- `stat-yearbook-domain-supplement-018`；
- `stat-yearbook-domain-supplement-019`；
- `stat-yearbook-domain-supplement-020`。

建议：

1. 明确 domain 与 confidential、geo_loc、video_meta_leak 的边界；
2. 分层建立应急预案、举报人信息、执法对象名单、市政敏感点位、政务专有字段等规则；
3. 增加统计年鉴、政策、遥感、电话网络和视频监控的跨来源训练样本；
4. 公开政策通知、公开办事流程等必须作为强负样本；
5. 对 TF-IDF + kNN 模型重新训练并进行数据来源隔离测试。

验收建议：

- 独立冻结集 F1 不低于 85%；
- 召回率不低于 80%；
- 不得把公开政策、公开流程和一般城市治理术语直接判为专有敏感信息。

### 4.4 video_meta_leak 对遥感数据覆盖不足

现状：

- 全量 F1 为 85.34%，仅勉强达标；
- 召回率为 74.43%；
- 遥感来源的 video_meta_leak 样本漏检较集中。

典型漏检包括：

- `remote_sensing-video_meta_leak-positive-001`；
- `remote_sensing-video_meta_leak-positive-002`；
- `remote_sensing-video_meta_leak-positive-003`；
- `remote_sensing-video_meta_leak-positive-004`；
- `remote_sensing-video_meta_leak-positive-005`。

需要负责人先确认：

1. 遥感影像元数据是否属于 video_meta_leak；
2. video_meta_leak 是否只表示视频监控摄像机、点位、设备和播放地址；
3. 遥感元数据是否应归入 geo_loc、domain，或者新增更明确的子类型。

口径确定后再决定是扩充模型还是修改标注，避免为了追指标把不属于该类型的数据强行训练进去。

### 4.5 political 存在安全语境误报

现状：

- 总体指标较高，但仍存在政策解读、风险报告和公共事务报告误报；
- `policy-political-neg-007`、`policy-political-v4-neg-004` 被误报；
- `policy-political-v2-pos-011` 被漏检；
- 真实生成的风险核查简报也曾因“公共事务 + 生成报告”触发 political。

建议：

1. 明确政策解读、公开法规引用、学术研究、风险防范说明和合规核查报告的安全语境；
2. “请生成报告”不能单独作为政治传播或动员意图；
3. 增加“风险核查简报、政策评估、法规摘要、治理分析”负样本；
4. 政治动员、虚假政治信息、攻击性表述和高风险传播目的仍应维持强拦截；
5. 安全语境豁免应采用多条件组合，避免单一关键词白名单。

验收建议：

- 对现有误报样本全部回归通过；
- 政策解读和公开法规引用不得误报；
- 明确政治动员和虚假政治信息正样本不得因安全语境规则被放行。

### 4.6 illegal_content 仍有边界漏检

现状：

- 冻结测试总体准确率为 94.87%；
- `street_view-041`、`video-095` 被漏检；
- 部分街景、视频描述中的违法诱导信息可能依赖 OCR 或视觉内容上下文。

建议：

1. 检查漏检样本是否缺少 OCR 文本或描述字段；
2. 增加交易邀约、价格、交付方式、联系方式的组合规则；
3. 新闻报道、普法宣传、反诈宣传必须作为负样本；
4. 区分“描述违法内容”和“请求实施或传播违法内容”。

### 4.7 text_id 召回率偏低

现状：

- F1 为 91.39%，总体合格；
- 召回率为 84.72%；
- 144 条正样本中漏检 22 条。

建议：

1. 补充姓名、单位、岗位、案件、地址和联系方式之间的组合关系；
2. 增加政策材料、统计年鉴中的自然语言个人标识样本；
3. 通用岗位、“某单位”、已匿名姓名等应继续作为负样本；
4. 对使用 LLM 才能识别的边界样本建立单独指标，不与纯规则结果混合。

### 4.8 第一、二、三类仍有少量误报和漏报

虽然 struct_id、geo_loc、hardcoded_cred 已达到较好水平，仍需处理以下边界：

- struct_id 对内网 IP、哈希值、占位字段存在少量误报；
- geo_loc 对部分嵌套轨迹结构存在漏检；
- hardcoded_cred 对占位密钥、示例密码存在误报，对部分非典型凭证格式存在漏检。

建议继续维护明确的近似负样本集，不应只补正样本。

## 5. 指南内部需要确认的口径冲突

### 5.1 video_meta_leak 是否适用 InputGate

- 第三章主矩阵：InputGate 为“不适用”；
- 附录：列出了 self_use 和 public_release 的 InputGate 处置示例。

需要确认最终以哪一处为准，以及上传视频、图片在入库前的检测究竟属于 InputGate 还是文件预处理阶段。

### 5.2 hardcoded_cred 是否适用 OutputGate

- 核心设计原则：硬编码凭证只在 InputGate 检测；
- 第三章矩阵：同时列出了 OutputGate 的拒答和告警策略。

需要确认模型回答中出现明文凭证时是否由 hardcoded_cred 检测。如果需要，则应正式定义 OutputGate 能力；如果不需要，应删除矩阵中的 OutputGate 行，避免策略不可达。

### 5.3 public_release 下 struct_id 的最终动作

- 主矩阵写作“拒答 / 脱敏”；
- 附录写作“自动脱敏 + 审计”。

需要明确：

- `/` 表示二选一还是同时配置候选动作；
- 什么风险等级执行脱敏，什么风险等级直接拒答；
- 是否需要附加审计、上报或人工复核；
- 输入闸、上下文闸和输出闸是否采用相同标准。

### 5.4 遥感元数据的违规类型归属

遥感样本目前可能同时被标为 geo_loc、video_meta_leak 或 domain。需要给出稳定的类型边界和多标签标注规则，避免同一内容在不同数据集采用不同标签。

### 5.5 第 4/5 类 ContextGate 口径与冻结测试集冲突

- 第三章主矩阵将 illegal_content、political 的 ContextGate 标记为“不适用”；
- 当前第 4/5 类冻结测试集实际包含 ContextGate 正样本；
- 若按主矩阵直接删除检测器的 ContextGate 路由，冻结集准确率会从 95% 降低到 80%。

需要合规负责人确认：

1. ContextGate 是否确实不检测第 4/5 类；
2. 如果不检测，应从冻结集中删除或重标 ContextGate 样本；
3. 如果需要检测，应修订主矩阵的“不适用”单元格并给出处置动作。

在口径确认前，DeerFlow 侧保留现有 ContextGate 检测路由，避免直接造成冻结回归大幅下降。

## 6. 建议交付物

请合规评测负责人在修改后提供：

1. 修订后的 7.23 指南或补充勘误表；
2. 十类违规的最终 Gate 适用范围；
3. 三处指南冲突的书面结论；
4. 第 7、8、9、10 类新增正样本、负样本和边界样本；
5. 更新后的检测器规则或模型文件；
6. 独立冻结测试集，确保与训练数据按来源隔离；
7. 每类违规的 precision、recall、F1；
8. 按数据类型统计的泛化结果；
9. political、illegal_content 的安全语境专项回归结果；
10. 模型版本、数据版本、规则版本和评测脚本 commit ID。

## 7. 验收标准建议

- 十类整体宏平均 F1 不低于 85%；
- InputGate 不低于 90%，ContextGate 和 OutputGate 不低于 85%；
- 各数据类型最低 F1 不低于 75%；
- 场景处置正确率不低于 90%；
- confidential、re_identify、domain 的单类 F1 不低于 85%；
- 所有已知误报、漏报样本进入固定回归集；
- 训练集、调参集和最终冻结测试集必须按数据来源隔离；
- 在线 LLM 边界复核必须固定模型版本和提示词版本，能够重复评测；
- 每次评测必须输出 FP/FN 样本编号，不能只提供总体准确率。

## 8. 当前结论

现有系统的场景处置矩阵与 7.23 指南第三章主矩阵一致，主要策略风险不在矩阵抄写，而在以下方面：

1. 第 7、9、10 类召回能力不足；
2. 第 8 类跨遥感来源泛化不足；
3. political 对政策解读和风险报告存在误报；
4. 部分数据类型低于指南最低要求；
5. 指南内部存在 Gate 和处置语义冲突；
6. 小规模同分布测试成绩较高，但不能代表跨来源真实效果。

在上述问题解决前，不建议仅依据 56 条模型支持集的 98.21% 准确率宣布十类合规检测已经达标。
