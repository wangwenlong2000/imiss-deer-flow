## 调研结论及适用边界

以下依据产品/开源项目官方资料，属于机制调研，不是各产品在本项目上的横向准确率排名。没有找到可直接代表本项目中文十类场景的通用商业成功率。

| 方法 | 已有实现与资料 | 对本项目的取舍 |
| --- | --- | --- |
| 训练意图分类器并联合抽槽 | [Rasa DIET 与 FallbackClassifier](https://github.com/RasaHQ/rasa/blob/3.6.x/docs/docs/components.mdx)；低分或前两名接近时可回退 | 本地运行可行，但现有少量资料不足以证明覆盖口语、否定、多意图和换话题；先积累标注，暂不增加训练系统 |
| 语义向量路由 | [Aurelio Semantic Router](https://github.com/aurelio-labs/semantic-router)、[路由阈值与校准](https://docs.aurelio.ai/docs/semantic-router/v1/user-guide/components/routers)；比较请求与示例的语义表示，支持本地编码器 | 可以作为未来快速通道或候选排序；需要中文验证集校准。不能把一个未经校准的相似度门槛替换成新的硬排除门槛 |
| 上下文驱动的结构化理解 | [Rasa CALM Dialogue Understanding](https://learning.rasa.com/rasa-pro/dialogue-understanding/)：结合对话状态、流程与槽位，生成结构化命令，支持澄清 | 借鉴理解与业务执行分离、流程说明与上下文共同参与判断；本项目仍保留十类 scene 接口，避免整体迁移框架 |
| 识别业务后补齐参数 | [Dialogflow CX Parameters](https://docs.cloud.google.com/dialogflow/cx/docs/concept/parameter) 提供会话参数、表单填充和追问；[Generative fallback](https://docs.cloud.google.com/dialogflow/cx/docs/concept/generative-fallback) 可使用当前输入、会话及流程说明 | 区分缺执行参数与缺领域对象。前者可先确定场景，后者需要澄清；不把缺文件或日期一律当作不认识该业务 |
| 本地约束结构化输出 | [vLLM Structured Outputs](https://docs.vllm.ai/en/latest/features/structured_outputs/) 支持 JSON Schema 等约束 | 本地服务部署后可按其实际版本启用。当前使用兼容的提示与 Pydantic 校验；没有向现有服务加入未验证的专属参数。格式有效不代表语义正确 |

本项目的工程判断：十类候选规模小，且同一轮还需抽取参数与生成 OneCityAgent 规划，先采用一次 Qwen 统一语义识别。暂不叠加 embedding、reranker 和第二个审查模型；新增每层需要有独立收益与延迟证据。明确闲聊/能力清单仍使用零模型路径，多轮对话控制可能另需一次模型判断。

## 当前实现

1. 默认使用部署配置中的十类完整场景，停止合并六个内置演示告警场景；技能过滤也校验部署注册表，防止旧会话的演示场景重新注入技能。
2. 所有十类始终可进入语义判断，取消生成前关键词裁剪与生成后关键词否决。规则仅作为服务不可用或结构化校验失败时的显式降级。
3. 场景说明定义处理对象、业务目标与边界，重点区分区域活动/道路运行、视频执行/源码分析、专业表格计算/结果制表、法律行政文书/普通写作。
4. 同一次调用返回任务、允许的参数、原文证据、初步规划、自评置信度与可选澄清问题。代码只校验场景白名单、参数名、格式及引文确实来自输入。引文存在不能证明分类语义正确；自评置信度未经校准，不用于硬阈值路由。
5. 仅传入最多 12 个附件的文件名/扩展名/MIME 元数据（每项最多 256 字符）及上一轮实际用户任务（最多 2000 字符），不读取附件正文，不将模型改写文本当作用户证据。文件名是线索，不是内容事实。
6. 真正信息不足时保留空场景和具体澄清问题，通过现有 todo guidance 引导执行智能体使用 ask_clarification；不是意图层直接发起前端中断。常规缺日期/范围等执行参数，规划阶段核验。
7. 正常业务识别一次模型调用；结构/引文校验最多修复一次，之后显式降级。规划略多于七步时本地合并尾部，避免仅因步数额外调用。保留规划字段与移动端 task_planning/规划智能体转发契约。

## 评估约定

- 同学原题 28 条保持文字、预期标签与来源不变，不添加文件夹名称或预期标签作为提示；只使用原评测已有附件元数据。不发送附件正文。用户已明确授权这 28 条发送到现有 DashScope。
- 原合成 96 条中排除预期包含六个演示场景的 12 条，余 84 条原文与标签不变，另存 `scripts/intent_eval_ten_scene_cases.json`，排除清单保留。
- 新增 20 条自建语义用例，首次调用前冻结，包含同一句模糊问句在视频/PCAP/无附件条件下的不同判断、否定、多意图、英文、普通输出与换话题。首次观察结果后作为回归探针使用，不能声称最终结果是未见测试集。
- 严格按场景集合完全相等判对，多报一个场景也算错。带澄清标签的用例另外考核是否生成问题，错误与超时保留在分母。
- 分开报告每组，记录调用次数、降级、规划产生与适配器转发、平均与 P95 时间。不执行具体技能、业务工具或发送外部平台请求，不能等同端到端任务成功率。

原题平均用时比关键词门槛版增加约 0.72 秒，准确率增加约 57.14 个百分点；不能声称这轮语义增强同时降低了同一原题集的平均耗时。正常路径已将最初多步识别合并成一次调用，本轮 28 题共 28 次、零修复。新探针的额外两次与旧集合的额外调用主要来自上下文对话控制。全部 28 条原题生成规划，移动端适配器测试中 28/28 可产生 task_planning/规划智能体片段；没有向真实 OneCityAgent 平台发送任务。

新增语义探针的场景集合为 20/20 正确，严格总分 19/20：`semantic-12` 是普通材料简报，模型返回空场景符合标签，但额外追问材料，按冻结的“不需要澄清”标签判错。不能将场景分数替代严格分数。

原题按来源类别的结果：交通流量 4/4、代码片段 2/2、时空轨迹 12/14、网络流量 1/1、遥感图像 2/2、视频监控 3/4、表格年鉴 1/1。街景材料只有图片，没有明确测试问题；政策法规和电话网络没有本批原题，这三类仅有合成测试覆盖。没有把图片内容外发以扩充本批原题评测。

### 保留的失败与限制

- `trajectory-doc-09`：“判断某些区域更像居住区、商业区、交通枢纽还是混合功能区。”最终保留未知并询问区域/数据源。它可以由轨迹、POI 或影像等多种数据支持，原文没有指定方法。加同批真实前文后仍未匹配预期轨迹场景。
- `trajectory-doc-10`：“把热点、异常、预测、事件影响等结果合并成统一的区域证据。”原文保留未知并澄清；加入同批轨迹热点问题作为前文后正确识别。这个单独对照不计入原始 28 题。
- `video-04`：ShanghaiTech/StreetModel 的文本与视频 embedding 能力验证仍被判为程序片段；加入同批视频管线前文后依旧误判。需要补足模型/业务能力注册信息或更有代表性的标注，而非声称普通对话历史已解决。
- `challenge-20`：复杂整治台账合规简报多报 `table_yearbook`，冻结预期仅 `policy_regulation`，因此 84 题中计为一题错误。仍存在将支持步骤当作独立业务的边界问题。
- 初版语义模型原题为 26/28，最终更保守的模糊领域处理为 25/28；如实保留各轮结果，不选最好一轮作为最终版本成绩。新增探针从 18/20 提高到 19/20，但已用于迭代，不是盲测。
- 单个前文问题不能替代完整业务状态、附件字段与上游产物；本轮只使用实际用户原文与有限文件元数据。尤其附件名不能说明其真实内容，也没有评测业务任务实际完成率。
