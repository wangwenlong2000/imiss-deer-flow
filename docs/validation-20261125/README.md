# 真实业务并发与合规专项验收

## 已完成整改

上传链路保留文本提取失败和检查未完成状态，撤回失败文件并恢复被覆盖的同名旧文件。Gateway 与 OneCity 页面透传拒绝原因、动作、完成标记、依据和审计编号，完整正常文本也有检查记录。页面依据实际动作区分告警、人工复核与拒绝，告警附件可按策略保留。

已知超限或提取失败的单元直接进入未完成拒绝及审计，避免继续对不可完成检查的内容运行检测器。TF-IDF 特征中的路径箭头正则改为从 token 起点搜索，消除无箭头长字符串的平方级回溯。`make compliance-assets` 安装流程会按已校验的上游文件重新应用相同补丁，避免重新安装后恢复旧行为。浏览器复测中，100000 字节重复文本在 2.440 秒内完成检查，210019 字节超限文件在 1.071 秒内返回 422，并确认文件不存在。

新增本人任务状态、取消和恢复接口。每次操作重新核验 IAM、会话和线程归属，恢复还校验受理问题哈希、最新任务及快照读取前后的轮次一致性。取消只有在原生任务进入明确终态后确认。页面网络重试仅加入原任务，最多自动重试三次，之后保留手动恢复与取消入口。

原生模型错误、超时、计算交付不完整和取消分别保留失败终态。完成兜底要求准确的原生任务状态为成功，澄清不能覆盖后续错误。城市超脑会话的共用侧栏跳转已修正。登录表单允许服务端已接受的合法邮箱和既存密码，注册规则保持原有要求。

新的 OneCity 部署准备包默认值调整为 **执行 3、运行与排队合计 6、单用户合计 2**。两执行任务与三执行任务均有实测批次，采用有限队列约束积压。两批代码、冷启动与任务顺序存在差异，指标比较按观测结果列示。现有部署配置的变更需通过准备包与发布流程应用。

## 复验与交付范围

根目录 `make onecity-verify` 运行 10 组隔离多用户 HTTP 联调，`make onecity-verify-faults` 运行恢复与故障注入。真实模型负载使用 `scripts/verify_onecity_business_load.py`，需要由 `scripts/verify_onecity_production.py prepare` 生成的私有测试账号状态。具体参数和运行摘要见业务材料。

合规与上传完整回归为 **731 项通过、1 项既有条件跳过**；Mobile/IAM 定向回归为 **84 项通过**。这些测试集合存在交集。客户端回归、Node 22 生产构建及浏览器结果独立记录。负载判分脚本另有 6 项回归，部署准备脚本 6 项回归、资源安装流程 5 项回归通过。源码与关键材料的摘要见 [验收清单](validation-manifest.json)。

合规数据已用于历史开发，新增 30 条也用于本次整改。严格集合准确率受到原单标签与多类型命中的差异影响，剩余 83 条、88 个额外命中已列入复核清单。新增 30 条严格匹配 29 条，剩一条为姓名和手机号同时命中两类。可选外部 LLM 边界复核未执行。

持续负载验收范围为上述六批、约五分钟的固定规模任务。资源采样为容器 CPU/内存和共享宿主 GPU，远端模型 GPU 不可见。受理至执行时间包含 HTTP、IAM、路由和轮询误差，首反馈可能是意图或规划。一般问答语义准确率、全天负载容量和远端 GPU 吞吐仍需各自的专项验收。

公开材料保留样例编号、合成样例、计数、时延、动作、哈希及检查结果。原始 SSE、线程标识和现场截图保存在权限受限的本地测试目录。临时账号清理时删除状态文件中的密码和令牌。

四个负载账号及两个浏览器账号已停用并撤销令牌，104 个负载测试会话及 11 个浏览器会话均按准确 ID 和本人归属停用。独立验证服务及浏览器已清理，私有数据和配置留存供复核。清理前后原 OneCityAgent 及其专用 Gateway/LangGraph 的容器 ID 和启动时间一致。记录见 [清理结果](cleanup.json)。

源码修复、页面改动和调度默认值已纳入本地项目。本次最终版本通过独立服务验证，现有业务入口继续使用其当前发布版本。
