# 文件交付后分析正文显示两遍的修复

日期：2026-10-29（北京时间）。用户在两个会话并行测试时发现，B样例在下载卡片前后各出现一遍分析表格与说明。

## 原因

读取对应会话的原生任务列表，只有一个成功run，未发现重复提交执行。消息顺序为：

1. AI调用`present_files`，该工具调用消息同时附带完整分析文字。
2. 工具返回文件交付结果。
3. AI生成正式最终答复，再次列出分析结果。

原前端在`assistant:present-files`分组里直接渲染第1条消息的Markdown，随后又通过普通回答组件渲染第3条。两个正文的ID和措辞均不同，因此消息ID合并不能消除这类重复。第3条包含正式合规检查元数据，第1条没有同样的最终输出检查标记。

## 修改

[消息列表](../frontend/src/components/workspace/messages/message-list.tsx)的文件交付分组只显示文件卡片，取消工具调用附带正文的单独渲染；保留后续正式答复及原合规展示路径。未更改后台执行、并发/排队配置、消息持久化或文件内容。

不是按文本相似度删除消息，也没有隐藏不同用户回合里的正常回答。既有会话重新加载时同样使用这套显示规则，不需要重新计算或修改历史记录。正文尚未完成时，文件卡片仍能显示。

## 验证

- 新增6项实际消息列表的组件渲染回归；修复前5项失败、1项通过，修复后6项全部通过。
- 覆盖交付正文与最终答复重复、流式中间阶段、改写/拒绝最终答复、刷新时raw/canonical消息合并、正常多轮同文回答、多附件保留。
- 与既有流模式及合规测试一起运行，共30项通过；TypeScript及改动文件ESLint检查通过。
- 将用户此次会话的真实`messages`和`raw_messages`通过生产分组/合并函数及真实`MessageList`组件回放，验证中间正文不展示、正式答复只出现一次、下载卡片保留一个。真实回放数据和会话标识保留本地，公开版本包含使用合成消息的回归测试。

组件测试替换了底层视觉组件及上下文hook，验证的是消息列表的渲染选择和分组，未进行完整浏览器视觉自动化。本轮没有再次调用模型，也没有改写用户会话或附件。
