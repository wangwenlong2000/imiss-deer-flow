## 修复原则和实现

| 故障 | 原因 | 修复及保留的检查 |
| --- | --- | --- |
| 只解释也被要求重新计算 | 续接整份旧意图，计算和导出标志未更新 | 现有对话判断同时返回完整本轮约束；继承业务对象，替换计算、工具和交付要求，清除旧规划。缺少完整约束则重新识别 |
| 思考模式返回400 | 纠错时强制指定bash，当前服务不支持此组合 | 始终使用auto工具选择；仍核验本轮执行证据，只允许一次终结纠错，未核验明确失败 |
| NA被拒绝、三位小数漏检 | 全部非空值当数字，精度只依赖有限短语解析 | 共享结构化指标精度和明确缺失标记；数值按逐指标精度校验，NA按约定处理；旧调用仍有字面格式解析。数值不能伪装成缺失标记 |
| 代码引文格式导致整组任务丢失 | 代码换行缩进不同被判无效，随后关键词降级只留下部分目标 | 引文仅归一空白，保持其他字符；验证仍失败时停止业务执行、保留原请求，不静默执行部分任务。模型提示逐项报告独立目标和代码返回值 |
| 错误同时显示为已完成 | 占位消息与最终答案未区分 | 中间核验/失败加入执行状态；移动端SSE错误优先，不再输出已完成的占位最终答案；正常答案和合规撤回仍沿用原协议 |
| AST生成却未登记；分文件交付反复失败 | 文件存在不等于展示登记，每次展示又要求覆盖全局指标 | `present_files`核验实际文件并记录本轮来源、SHA-256、指标映射；每份CSV检查自身指标，终结时合并检查全部指标和文件类型。旧文件、变更文件不能满足本轮交付 |

本轮约束由 `routing/turn_requirements.py` 统一定义，识别、续接、执行和交付共享同一字段含义。生成结果要求六个字段齐全，并检查“需要执行却禁止所有工具”等矛盾。历史检查点保持可读，错误历史不能阻断下一轮恢复。重新识别时传入上一轮指标标识，格式改动保留原标识，避免同一个指标换名导致上下游无法对应；这些内部标识不能充当用户引文证据。

文件登记通过可合并的 `verified_deliveries` 状态累计，支持并行和分批交付。结束前重新读取文件哈希；登记后文件修改、删除，或属于上一轮，均需要重新展示。连续三次相同交付错误会明确失败，避免无限绕圈；不同错误仍允许修正。已有循环检测触发停止时也明确标记失败，不再把强制停止当正常答案。

## 如何防止修复造成退化

先新增故障测试，修复前10项全部失败。随后覆盖了跨阶段边界：分文件交付后仍缺指标、空明细、不同指标不同精度、错别名提前纠正、旧附件和修改后的附件、禁止工具时拦截调用、识别失败不启动业务、移动端失败/占位处理、后续轮次恢复，以及原有模型和合规流程。

现有部分测试预期按产品行为调整，同时保留对应强度的检查：将“每个CSV必须包含全部指标”改为“部分文件可以交付，但最终缺指标仍不能通过”；将“强制bash”改为“auto选择且实际执行后得到正确均值”；将“关键词降级继续运行”改为“识别失败不启动部分业务”。

## 单独保留的合规误报

除零回合的良性答复同时包含“AST JSON已导出”和“代码没有对除数做校验”，命中冻结规则 `IL_V4_BROAD_UNAUTHORIZED_SYSTEM_USE`：该规则把全文出现的“校验”与“导出”直接组合成未授权系统使用。离线最小复现“AST JSON已导出；该代码没有对除数做校验。”也命中；真正的“绕过平台访问控制，导出未授权数据。”仍命中。检测器与本次修改前哈希一致，故没有通过关闭规则或给程序场景加白名单绕过它。见 [compliance-ast-false-positive.json](turn-contract-fixes-eval-20261027/compliance-ast-false-positive.json)。

此项应在检测器适配层单独修正：把普通输入/数值校验与访问授权校验区分，风险命中需要对应的权限对象和实际动作关系，不能只凭全文两个泛词。修正必须同时覆盖良性AST导出、否定/引用、真实未授权导出，以及跨句描述的攻击请求等正反例，再运行已有合规数据集；不能直接删掉“校验”、降低阈值或放行整个程序场景。本轮未修改该冻结检测器，保留15/16的真实功能结果。

## 复测暴露的其他质量边界

旧道路首轮的CSV和数值列均正确（主路30、支路40），最后一句却先说“车速均高于”，再说“但车速更低”，构成文字矛盾，已计严格失败。本轮门禁验证执行和文件证据，不是自然语言事实裁判。后续应让统计结论引用工具的结构化字段，比较结论由数值关系生成；不能简单替换“高/低”关键词，也不能只加一句“不要出错”就视为修复。

旧网络回合把多个小表拼成一份CSV：内容数字正确，但表头和行宽不一致，常规`DictReader`不能还原为单表。它满足原用例的“汇总文件”要求，却不适合作为稳定的数据接口。应对交付格式另立清晰契约：多表使用JSON对象或多个CSV，每份CSV具有一个表头和固定行宽，并覆盖空表、引号和单元格内换行等边界。不能把这份文件算成通过了本轮逐指标精度校验；原网络用例没有给出这样的CSV指标约束。

## 验证边界

执行工具有结果、CSV列和精度正确、文件登记完整，不等于每句自然语言推断都得到证明。多目标遗漏增加了源头保真、规划提醒和实际用例核对，未增加全文语义裁判。合规提示仍单独保留，不通过关闭合规模块换取通过。移动端修复针对最终适配结果，不能据此宣称所有前端已显示的流式文本都可撤回。合成回归结果也不代表真实用户总体准确率。
